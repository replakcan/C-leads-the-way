Using the this Pointer
    Every object has access to its own address through a pointer called 'this' (a C++ keyword).
    An object's this pointer is not part of the object itself--i.e., the size of the memory occupied by the tis pointer is not reflected in the result of a sizeof operation on the object. (passed implicitly by the compiler to each of the object's 'non-static' member fxns)
        x = 12;
        this->x = 12; // pointer notation
        (*this).x = 12; // dereferencing the pointer first

    cascadeed fxn calls with this keyword
        by returning *this with member-fxns, you can chain member-fxns.
            class Time{
                public:
                    ...
                    Time &setTime(int, int, int){
                        ...

                        return *this;
                    }
                    ...
                private:
                    ...
            };

    for classwide informations

        class Martian{
            static int martianCount = 0;
        };

    The static members of the class need to be avaliable from any client code that access the file, so we cannot declare them static in the .cpp file--we declare them static only in the .h file.

Data Abstraction and Informatin hiding
    The client cares about WHAT functionality a stack offers, not about HOW that functionality is implemented. -> data abstraction.
    Many programming languages emphasize actions. In these languages, data exists to support the actions that programs must take.
        Data is "less interesting" than actions. Data is "crude".
        Only a few built-in data types exist, and it is difficult for programmers to create their own types. C++ and the object-oriented style of programming elevate the importance of data. The primary activities of OOP in C++ are the creation of types and expression of the interactions among objects of those types. To create languages that emphasize data, the programming-languages community needed to formalize some notions about data. The formalization we consider here is the notion of "abstract data types(ADTs)", which improve the program development process.

    The point is that even the built-in data types provided with programming languages lie C++ are really only approximations or imperfect models of real-world concepts and behaviors. Types like int, double, char and others are all examples of abstract data types. They are essentially ways of representing real-world notions to some satisfactory level of precision within a computer system.

Critical Memory Management Issue(The Rule of Three)
    Your code contains a severe bug regarding memory management. You are managing a raw pointer (ptr) in SavingsAccountInterface and deleting it in the destructor, but you have not defined a Copy Constructor or an Assignment Operator.
        
        void someFunction() {
            SavingsAccountInterface acct1(1000.0);
            SavingsAccountInterface acct2 = acct1; // Default copy constructor runs
        } // Destructors run here

        1.acct2 copies the pointer address from acct1. Both point to the same SavingsAccountImplementation.
        2.acct1 is destroyed -> delete ptr happens.
        3.acct2 is destroyed -> delete ptr happens again on the same address.
        4.Result: Double Free Corruption (Program Crash).

    If you must use raw pointers (C++98 style), you must implement the copy constructor to create a new Implementation object with the same values.
